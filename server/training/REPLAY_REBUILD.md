# Natural-Flow Replay Rebuild — Design

Rebuild Ava's adapter + derived state after manual corruption repair, by
**replaying the intended nightly cron cadence** over the surviving chat corpus
instead of collapsing everything into one build. GPU cost is not a constraint;
fidelity of the *causal state chain* is the goal.

Status: design only. Requires the implementation deltas in §8 before it runs.

---

## 1. Core principle — frozen corpus, replayed cadence

The **chat transcripts are the ground truth and the only frozen input.**
Everything else (sidecars' reflect-once targets, RAG memory, the consolidation
ledger, the persona digest, the wander corpus, the adapters) is *derived* and is
reconstructed in causal order by replaying each night.

The replay **never regenerates chat content.** Anything in the natural flow that
*creates* new chats (autonomous outreach / synthesis openers) is NOT re-run — if
a historical Ava-initiated session exists as a transcript it is reflected like
any other chat; if it doesn't, we cannot recreate it faithfully and do not try.

Granularity is **one cycle per day-that-has-chats** (the nightly cron boundary
is the real one, not an approximation). Empty nights collapse away: an
intermediate adapter's only consumer is the *next* reflection, so a night with
no new chats produces an adapter nobody reads. `N_cycles = distinct chat-days`.

## 2. The state chain — what actually carries night k → night k+1

| Channel | Produced by (night k) | Consumed by (night k+1) | Reconstructed? |
|---|---|---|---|
| **Adapter weights** (`adapter_id`) | `train_cycle`, `built_at = day k` | Reflection **authoring** runs on base+adapter_k | ✅ reload before next reflect |
| **RAG memory** (`rag_memory.jsonl`: asks/facts/persona + `from_weights` mirror) | reflection writer → staged → committed | reflection RAG recall (`before_session`), resolve-and-distill | ✅ commit each night, in order |
| **Consolidation ledger** (`consolidation_anchors.jsonl`) | writer (persona/fact anchors) + **fact placement** (`source_exchange`) | persona-digest fold **and** training persona/fact CoT injection | ⚠️ needs clean-base (§3a) for fact hosts |
| **Persona digest** (`persona/current.json`) | digest pass (gated on raw fingerprint) | branch **judge** target, maturity gate, revision "who I'm becoming" context | ✅ digest runs; ⚠️ judge consumer needs §3 |
| **Sidecars** (`.state.json`: verdict/target/`reflected_at`) | reflection | training reads targets | ✅ regenerated by re-reflection |
| **Tension** (in the **transcript** `<ts>.json`) | generation (chat time) | **branching** reads `token_ids`/`alt_token_id` | ✅ **survives the wipe** (§3b) |
| **weights_persona.jsonl** | writer | provenance only (training reads the ledger, not this) | ✅ committed, low criticality |
| **Wander corpus** (`data/til/wander.jsonl`) | autonomous idle wander | training injection (fixed LR) + chat/reflect RAG (age-faded) | ⚠️ must be **date-gated** to ≤ day k (§6) |

## 3. Two channels the naive path silently drops — READ THIS

### 3a. The headless CLI omits the clean-base pass → **fact placement + judge are skipped**

`reflection_run.py` calls `runner.execute_run(...)` **without `clean_base_ctx`**
(reflection_run.py:1056; runner gate at reflection_runner.py:562). With no
`clean_base_ctx`, the phase-two clean-base batch never runs, so **both**:

- **Fact placement** — assigns each unhosted `[fact]` a host exchange and
  snapshots `source_exchange` onto the anchor. Without it, facts have **no
  host**, so `train_cycle`'s fact-CoT injection (`fact_render.py`, sourced per
  host from the ledger) injects **nothing**. Facts silently vanish from the
  training corpus.
- **Branch judge** (the persona-driven target override) — never runs.

The **persona digest itself DOES run in the CLI** (reflection_runner.py:536, not
gated on clean-base), so persona still forms — but its most direct effect on the
*trained target* (the judge override) is dropped.

➡️ **The replay driver must supply `clean_base_ctx`** (the `CleanBaseSession`
adapter-swap), or it is not reproducing natural flow. This is the single most
important delta.

### 3b. Tension lives in the transcript, so the wipe keeps it → **branching is ALIVE**

Tension is written into the **transcript** `chats/<ts>.json`, not the sidecar:
`chat_logger.log_exchange` puts `entry["tension"] = tension` into the session
doc that `_save()` writes to the `.json` (chat_logger.py:182). The `.state.json`
sidecar holds only consolidation state — verdict/target/`reflected_at`
(chat_sidecar.py:1). Branch replay reads tension from the transcript in the
chats dir (branch_replay.py:160), never from the sidecar.

The wipe deletes only `*.state.json` / `*.shareml.json`; the `<ts>.json`
transcript is **kept** (and archived ones are restored to hot). So the tension
series (`token_ids` + contested `alt_token_id`) **survives the wipe**, and
branch replay is fully eligible on the recovered corpus.

Consequences (the reverse of what an earlier draft claimed):
- **Branch-win targets are available** — branch generation replays the contested
  tokens under the currently-loaded adapter (`adapter_{k-1}` in the loop), i.e.
  the authentic "what the self-as-of-that-night would have said instead."
- **The persona→branch-judge→target-override channel is reproducible** — given
  `clean_base_ctx` is wired (§3a) *and* the branch generate/chooser fns are wired
  (the headless CLI already wires those — reflection_run.py:1027).

Only genuinely tension-less exchanges stay branch-ineligible: chats **logged
before the tension-capture extension existed** (branch_replay.py:157). That is
independent of the wipe — verify your corpus's oldest chats actually carry a
`tension.token_ids` series; anything predating capture trains on
revision-derived targets only.

### 3c. `[fact]` → weights runs *entirely* through §3a — no clean-base, no facts in the model

Facts never train as their own rows. A fact reaches the weights only by being
**injected as an `"I know that …"` line into the `<think>` of a real dialogue
exchange that is already being trained** — its *host* (`fact_render.py`;
`build_dataset._inject`). Two hard gates decide whether that happens:

1. **The host must exist.** `build_dataset._live_hostable_anchors`
   (build_dataset.py:150) admits a fact **only if
   `source_exchange.exchange_index is not None`** — and `source_exchange` is set
   *only* by the clean-base **fact-placement** pass. No clean-base → no
   `source_exchange` → the fact is **silently excluded from every build**. It
   survives as `from_weights` RAG recall, but it is **never trained**.

   This is the asymmetry to internalize: **persona injection does not need
   clean-base** — a persona anchor carries its host natively (the
   distilled-from exchange, build_dataset.py:80). **Fact injection is 100%
   dependent on clean-base.** So wiring `clean_base_ctx` (§3a) is not a
   refinement for facts — it is the entire `[fact]`→weights channel.

2. **The host row must be in the trainable window at build time.** Injection
   rides the host exchange's *dialogue row*, and that row is emitted only when
   the bundle's wall-clock age gives `lr_multiplier > 0` — i.e. the host chat is
   past the ~24 h RAG-only window (build_dataset.py:226). Fact placement is
   **chat-local** (host is within the fact's own chat), so a fact born on night
   k (from chat C, then <24 h old) is **not** trained on build k — its host is
   still RAG-only. It **graduates into weights on build k+1**, when chat C ages
   into the ramp, and injects on *every* build thereafter (the ledger is read
   immutably — build_dataset.py:142).

**Replay consequence:** the fact→weights schedule is reproduced *for free* by
the nightly `built_at` advance — a fact enters the model exactly one cycle after
its chat, riding the same wall-clock graduation as the dialogue it annotates —
**provided** (a) `clean_base_ctx` is wired so placement stamps `source_exchange`
(§3a), and (b) the ledger accumulates in order before each build (§2). By the
final settle-build (`built_at = now`), every placed fact's host is well past the
window, so all placed facts are in the shipped adapter. Caps: ≤2 personas then
≤2 facts per host `<think>`, deduped against the existing CoT
(`PERSONA_INJECT_CAP` / `FACT_INJECT_CAP`); the old cumulative `FACT_TRAIN_CAP`
is retired under the rebuild.

## 4. So — does persona affect the next cycle? (your flagged concern)

**Yes — through four channels, all reproducible.** Post-wipe, persona propagates
to night k+1 by:

1. **Weights** — persona CoT is injected into `adapter_k`'s training corpus (via
   the ledger anchors), so the adapter that *authors* night k+1's reflection has
   the persona baked in. This is the primary, load-bearing channel. ✅ works,
   *provided* the ledger accumulates persona anchors before each build.
2. **RAG recall** — the `from_weights` persona mirror in `rag_memory.jsonl` is
   retrieved during night k+1's reflection. ✅ works with ordered commits.
3. **Revision context** — the digest feeds the "is this who I'm becoming?"
   framing. ✅ digest regenerates each night.
4. **Branch judge → trained-target override** — the clean-base judge applies the
   digest to re-point the trainable target toward the branch that best matches
   "who I'm becoming." ✅ **reproducible** — tension survives (§3b) so branches
   exist, and the judge runs given `clean_base_ctx` (§3a). It is maturity-gated
   (≥2 themes at recurrence ≥3), so it stays dormant early and wakes as the
   corpus matures — which the night-by-night replay reproduces correctly.

**Timing bonus from night-by-night:** the judge override (were it alive) and the
digest maturity gate (≥2 themes at recurrence ≥3) are *dormant on a thin corpus*
and wake as persona matures. A collapsed single build would present a
fully-mature digest from token one and mis-fire everything at once. Replaying
per-night reproduces the correct dormant→mature ramp for free.

## 5. The replay loop

```
sort chats by day; days = distinct calendar days with ≥1 chat
adapter = base            # server_config.adapter_id = null after wipe
persona/ledger/rag = empty (post-wipe)

for k, day in enumerate(days):
    load(base + adapter)                       # adapter = adapter_{k-1}; base on day 0

    # ---- REFLECT (authored by the self as of day k-1) ----
    reflect(chats_of[day],                      # under current adapter + digest
            clean_base_ctx=CleanBaseSession,    # §3a — REQUIRED (fact placement)
            now := day,                          # §6 simulated clock
            ingestion=off,                       # §9 external news irreproducible
            revisit_head=<knob, §7>)
    commit staging -> live                       # rag_memory, ledger, sidecars, weights_persona
    #   persona digest regenerates inside execute_run (fingerprint-gated)

    # ---- TRAIN (fresh LoRA from frozen base) ----
    adapter_k = train_cycle(built_at = day,      # §6 — REQUIRED new flag
                            corpus = all committed bundles with chat_ts <= day,
                            wander <= day)        # §6 date-gate
    server_config.adapter_id = adapter_k

# ---- SETTLE TO PRESENT ----
adapter_final = train_cycle(built_at = now,      # re-age whole corpus to today
                            corpus = all bundles, wander = all)
server_config.adapter_id = adapter_final
```

Off-by-one is deliberate and correct: night k reflects using **last night's**
adapter (`adapter_{k-1}`), then produces `adapter_k`. That matches "reflect with
current weights, then produce tonight's weights."

The intermediate adapters exist **only** to be authentic reflectors; only
`adapter_final` (or `adapter_D` if `now == last chat day`) ships. Keep the
intermediates as lineage for rollback, or discard.

## 6. The simulated clock

Three places read wall-clock "now"; all must be pinned to `day k`:

1. **Training `built_at`** — `build_dataset(built_at=...)` already accepts it
   (build_dataset.py:175), but `train_cycle.main()` hardcodes
   `datetime.now()` (train_cycle.py:1216). **Add `--built-at ISO`** threading
   into that line. Row wall-clock ages, LR ramp, and the RAG-only youngest
   window are all measured against it, so this alone reproduces the correct
   age-weighting *as of that night*.
2. **Reflection RAG age-fade + wander recall** — the reflection RAG must not
   retrieve wander/memory items *newer* than day k. Age-fade already down-weights
   old items; the missing piece is a **future cutoff** so day-k reflection can't
   see day-(k+3) wander. Add an `as_of` filter to the wander channel (and, if you
   want strictness, to reflection-memory recall) keyed off the run's simulated
   now.
3. **Wander training injection** — filter `wander.jsonl` to `captured_at <= day
   k` when assembling `wander_pending` for build k. The final settle-build uses
   all of it.

News ingestion (Wikipedia current-events) is external and time-varying — it
cannot be reproduced as-of a past night. Leave it **off** for the replay (§9).

## 7. Determinism knobs (revisit / synthesis / RNG)

Natural steady-state runs a **revisit head-phase** every night (re-reflect one
aged chat under the *current* persona, mutating its target). Reproducing it is
more faithful — old chats drift toward the maturing self instead of being frozen
at their original night's self — but it is **stochastic** (random pick, reads
`revisited.jsonl`) and makes the rebuild path-dependent.

- **Recommended for a recovery rebuild: revisit head-phase OFF.** Each chat is
  reflected once, under the adapter/persona of its own night. Deterministic,
  debuggable, and the corruption you're recovering from is easier to reason
  about against a deterministic baseline.
- **For maximum steady-state fidelity: ON, with a seeded RNG** so the pick
  sequence is reproducible. Only choose this if you specifically want the
  "old chats re-derived under evolving self" behavior in the shipped artifact.

Autonomous synthesis/outreach: not reproduced (they mint new chats — see §1).

## 8. Implementation deltas required

1. **`train_cycle --built-at ISO`** — thread into train_cycle.py:1216
   (`build_dataset` already supports it). *Small.*
2. **A replay driver** that, per day: loads base+adapter_{k-1}, runs reflection
   **with `clean_base_ctx` wired** (the CLI's missing piece — reuse
   `agentic.CleanBaseSession` the way `reflection_service` does, not the bare
   `reflection_run.py` path), commits, calls `train_cycle --built-at day`,
   repoints `adapter_id`, loops; final settle-build at `now`. *Moderate — this
   is the real work. It is `reflection_run.py` + `clean_base_ctx` + a day loop +
   the train invocation, minus the ingestion/head-phase the service adds.*
3. **Wander/reflection-memory `as_of` cutoff** (§6.2, §6.3) — a future-timestamp
   filter on the wander channel and the wander-pending assembly. *Small–moderate.*
4. **(Optional) seeded revisit** if §7 ON is chosen. *Small.*

The corpus builder, decay math, label masking, persona digest, and fact
placement all already exist and are reused unchanged — the deltas are the clock
flag, the driver, and the as-of gates.

## 9. Fidelity ledger

**Faithful (reconstructed exactly, given `clean_base_ctx` + branch fns wired):**
- Per-night from-scratch adapter with correct wall-clock age-weighting (`--built-at`).
- Reflection authored by the evolving adapter (the whole point).
- Persona via weights-injection + RAG recall + digest **+ branch-judge override**,
  with correct dormant→mature timing (§4).
- Branching / branch-win targets — tension survives the wipe (§3b).
- Fact CoT injection (given clean-base wired, §3c).
- Ordered RAG-memory / ledger accumulation.

**Approximated:**
- Old-chat target drift (revisit head-phase) — off by default (§7).
- `surfaced_in` ask→answer linkage: asks were surfaced into sessions at *chat*
  time; chats are frozen and can't re-surface, so consolidation's
  resolve-and-distill won't auto-fire for historically-surfaced asks. Answers
  still exist in the transcripts as ordinary content; only the auto-distill
  shortcut is missing. Minor.

**Impossible / lost:**
- Branch replay on any chat **logged before the tension-capture extension** —
  those exchanges have no `token_ids` series and train on revision-derived
  targets only (§3b). This is a per-chat property of the corpus, not a
  wipe consequence; check your oldest chats.
